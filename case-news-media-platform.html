Overview

A complete publishing product, not just a news homepage.

The platform combines a fast, SEO-focused public website with a full admin dashboard. Visitors can browse categories, articles, authors, tags and search, while staff manage content and publishing operations through a protected newsroom.

The Challenge

  • One connected editorial workflow. Articles, authors, categories, media, redirects and publishing schedules need to work together instead of living in disconnected tools.
  • Public performance and private administration. Public pages should be cacheable, while admin pages and mutations must remain authenticated and permission-checked.
  • Publishing needs more than a text editor. A newsroom also needs structured metadata, media handling, scheduled releases, feeds, redirects and operational logs.

My Role

I built the platform end to end: the Next.js application, public page system, admin dashboard, Supabase data and authentication integration, publishing workflows, technical SEO, security layers, automated tests and Vercel deployment.

What I Built

  • Public news website: homepage, category pages, article pages, author profiles, tags, search, policy pages, RSS feeds and XML sitemaps.
  • Admin newsroom: article management with a Tiptap editor, categories, authors, media library, advertising settings, redirects, editorial calendar, scheduled publishing, logs, subscribers and site settings.
  • Publishing workflows: scheduled publishing, RSS feed imports and connected editorial automation endpoints for content review and operational checks.
  • Technical SEO: page metadata, canonical URLs, Open Graph and Twitter cards, JSON-LD structured data, XML and Google News sitemaps, robots rules, redirects and noindex handling.
  • Security: Supabase authentication, writer/editor/admin roles, PostgreSQL Row Level Security, Zod validation, server-side HTML sanitisation, verified media uploads, rate limits and protected cron endpoints.

Architecture and Performance

The application uses the Next.js App Router with Supabase for PostgreSQL, authentication and file storage. Public pages use a cookie-less anonymous Supabase client so they can be statically rendered and cached with incremental static regeneration.

Admin actions use authenticated server-side access, check staff roles and rely on database Row Level Security for a second permission boundary. Mutations revalidate affected public paths so editorial changes appear without waiting for the full cache interval.

Public request

Public pages query published content through the anonymous client and use a five-minute ISR revalidation window.

Editorial action

Staff sign in to the admin dashboard; server actions validate input and check the required role.

Database enforcement

Supabase Row Level Security enforces access rules again at the database layer.

Publish and refresh

Scheduled publishing records the release and revalidates public pages so the latest content is available.

Quality and Reliability

  • TypeScript type checks and ESLint run as part of the project validation workflow.
  • Unit tests and database tests cover application logic, migrations and access-control behaviour.
  • Browser and accessibility checks cover key admin, publishing, SEO, responsive and public-site flows.
  • Uploads are checked by file content and re-encoded before being stored; article HTML is sanitised before saving.

Results

  • One newsroom: public publishing and the editorial admin are connected through a single application.
  • Editorial operations: articles, media, authors, categories, redirects and publishing schedules are managed from the dashboard.
  • Search-ready foundations: structured metadata, canonical URLs, sitemaps, RSS and schema markup are built into the platform.
  • Layered access control: authenticated roles, server-side checks and database-level RLS protect staff operations.

Takeaway

The key engineering decision was separating public read paths from authenticated editorial actions. That keeps public pages cacheable while admin operations remain protected by server-side role checks and database-level policies.
