How I rebuilt and optimised a 500+ product Shopify store

Diviniti is a luxury gifting brand with a catalogue of more than 500 products. I rebuilt how the store loads images, built a section system the merchandising team can use without a developer, and set up tracking and on-page SEO.

Overview

A luxury catalogue where page speed and merchandising flexibility both mattered.

The work covered the Shopify theme end to end: how images load, how pages are built and edited, and how customer behaviour is measured. At 500+ products, any inefficiency in how one image or section is handled repeats across every collection and product page — so the fixes had to be systemic, not page by page.

The Problem

  • Slow image loading. The existing image architecture was holding back load times on an image-heavy catalogue.
  • Merchandising depended on a developer. The theme had no flexible section system, so routine page changes needed code edits.
  • No structured tracking. The team had no clear view of how customers behaved on the site.

My Role

I owned the Shopify theme work: responsive image delivery, custom Liquid sections with merchant-facing settings, the analytics and behaviour-tracking setup, and on-page SEO across the catalogue. The merchandising team was the day-to-day user of the section system, so it was built for them to use on their own.

Technical Challenges

  • Sending each device an appropriately sized image across a large, image-led catalogue.
  • Giving non-developers control over page layout without handing them ways to undo the performance work.
  • Applying SEO structure consistently across 500+ products rather than one page at a time.

What I Built

  • Image-loading architecture — responsive sizes, a lazy-loading strategy and separate mobile and desktop images.
  • 20+ custom Liquid sections with JSON schema settings, so the team can add, edit and reorder page content in the Shopify editor.
  • Google Tag Manager and Microsoft Clarity for structured event tracking and heatmaps.
  • Structured on-page SEO across the full catalogue.

Performance Work

40% LCP improvement — Largest Contentful Paint, the time until the main content of a page is visible.

Responsive sizes

Images are requested at widths that match where they are displayed, instead of one large file for every screen.

Lazy-loading strategy

Images further down the page wait until they are needed, so they don’t compete with the main image for bandwidth.

Mobile and desktop image pickers

Separate images for mobile and desktop, so phones aren’t sent desktop artwork.

The Hard Part

Speed and flexibility pull in opposite directions: a section system that lets anyone place any image anywhere can quietly undo performance work. So the image architecture and the section system were treated as one problem. The mobile and desktop image pickers live in the section settings — when the team builds a new page in the editor, the responsive image behaviour comes with it.

Simplified sketch of the pattern — not the production code

{%- comment -%} Banner section: separate art for mobile and desktop {%- endcomment -%}
{%- liquid
  assign desktop = section.settings.image_desktop
  assign mobile  = section.settings.image_mobile | default: desktop
-%}
<picture>
  <source media="(max-width: 749px)"
          srcset="{{ mobile | image_url: width: 750 }}">
  {{ desktop | image_url: width: 1600
             | image_tag: widths: '800, 1200, 1600', sizes: '100vw' }}
</picture>

{% schema %}

  { "type": "image_picker", "id": "image_desktop", "label": "Desktop image" },
  { "type": "image_picker", "id": "image_mobile",  "label": "Mobile image" }
] }
{% endschema %}

Business Impact

Improving landing-page performance reduces friction for paid and organic visitors and can decrease abandonment before users engage with the store. For a luxury catalogue promoted through ad campaigns, that friction is present on every visit.

The section system paid off differently: the merchandising team could keep shipping page changes without waiting for a developer, and the tracking setup gave them a view of how customers actually used the site.

Results

  • 40% LCP improvement from the image-loading rebuild.
  • 20+ sections the team edits and reorders in the Shopify editor, without code changes.
  • Behaviour tracking through Google Tag Manager and Microsoft Clarity.
  • Consistent on-page SEO across 500+ products.

Takeaway

Performance work lasts longer when it is built into the tools the team uses every day. Because the responsive image behaviour lives inside the sections, pages the team builds later keep it without a developer re-checking each one.
