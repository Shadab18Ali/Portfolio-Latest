Overview

A luxury catalogue where page speed and merchandising flexibility both mattered.

The work covered the Shopify theme end to end: how images load, how pages are built and edited, and how customer behaviour is measured. With 500+ products, any inefficiency in one image or section repeats across every collection and product page, so the fixes had to be systemic.

The Challenge

  • Slow image loading. The image setup was holding back load times on an image-heavy catalogue.
  • Merchandising depended on a developer. The theme had no flexible section system, so routine page changes needed code edits.
  • No structured tracking. The team had no clear view of how customers behaved on the site.

My Role

I owned the Shopify theme work: custom Liquid sections with merchant-facing settings, product and collection features, responsive image delivery, the analytics setup and on-page SEO across the catalogue. The merchandising team was the day-to-day user of the section system, so I built it for them to use on their own.

What I Built

  • 20+ custom Liquid sections with JSON schema settings, so the team can add, edit and reorder page content in the Shopify editor.
  • Product experiences and collection filtering built with Liquid, JavaScript and metafields.
  • Image-loading architecture: responsive sizes, a lazy-loading strategy and separate mobile and desktop images.
  • Analytics integrations: Google Tag Manager, Google Analytics, Meta Pixel and Microsoft Clarity.
  • Structured on-page SEO across the full catalogue.

Key Improvements

Responsive sizes

Images are requested at widths that match where they're displayed, instead of one large file for every screen.

Lazy-loading strategy

Images further down the page wait until they're needed, so they don't compete with the main image for bandwidth.

Mobile and desktop image pickers

Separate images for mobile and desktop, so phones aren't sent desktop artwork.

The Hard Part

Speed and flexibility pull in opposite directions. A section system that lets anyone place any image anywhere can quietly undo performance work. So I treated the image setup and the section system as one problem: the mobile and desktop image pickers live in the section settings, and every page the team builds in the editor keeps the responsive behaviour.

Simplified sketch of the pattern, not the production code

{%- comment -%} Banner section: separate art for mobile and desktop {%- endcomment -%}
{%- liquid
  assign desktop = section.settings.image_desktop
  assign mobile  = section.settings.image_mobile | default: desktop
-%}
<picture>
  <source media="(max-width: 749px)"
          srcset="{{ mobile | image_url: width: 750 }}">
  {{ desktop | image_url: width: 1600
             | image_tag: widths: '800, 1200, 1600', sizes: '100vw' }}
</picture>

{% schema %}
{ "name": "Banner", "settings": [
  { "type": "image_picker", "id": "image_desktop", "label": "Desktop image" },
  { "type": "image_picker", "id": "image_mobile",  "label": "Mobile image" }
] }
{% endschema %}

Business Impact

Improving landing-page performance reduces friction for paid and organic visitors and can decrease abandonment before users engage with the store.

The section system paid off differently. The merchandising team could ship page changes without waiting for a developer, and the analytics setup showed them how customers actually used the site.

Results

  • 20+ sections the team edits and reorders in the Shopify editor, without code changes.
  • Responsive image delivery across an image-heavy, 500+ product catalogue.
  • Analytics through Google Tag Manager, Google Analytics, Meta Pixel and Microsoft Clarity.
  • Consistent on-page SEO across the catalogue.
