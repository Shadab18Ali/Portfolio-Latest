Overview

A made-to-order store where every product is personal, so every unconfirmed order has a real cost.

Customers choose a portrait's size, frame and finish, and the store produces it to order. I built the product-option logic, the collection filtering and a WhatsApp-first order check, and optimised the storefront for mobile shoppers.

The Challenge

  • Complex variants. Size, frame and finish combinations had to be clear on the product page.
  • Filtering without another app. Collections needed filtering, but the store was avoiding paid Shopify apps.
  • Fake COD orders. Unconfirmed cash-on-delivery orders are a common problem for personalised products in India. Here, each one meant a portrait produced for nobody.

Constraints

  • No paid filter or variant apps. The store had to stay lean, without recurring subscriptions.
  • Verification had to happen before production, not after a failed delivery, because a personalised portrait can't be resold.
  • Most traffic for personalised gifting arrives from mobile ad clicks, so every flow had to work well on a phone.

My Role

I wrote the collection filtering in JavaScript, the product-option logic in Liquid and the WhatsApp verification flow through WATI, and tuned the storefront layout for mobile.

What I Built

  • Custom Liquid product-option logic for the size, frame and finish combinations, with metafield-driven product content.
  • App-free collection filtering in JavaScript, in place of a paid filter app.
  • A WhatsApp-first COD verification flow through WATI, so orders are confirmed before fulfilment.
  • A responsive, mobile-first storefront for shoppers arriving from ads.

Key Improvements

Order placed

WhatsApp confirmation

Confirmed before production

The team only produces confirmed orders. Unconfirmed ones are caught before any material or time is spent.

The Hard Part

Why custom code instead of another app? A filter app would have added a monthly fee and more third-party script to every collection page, on a store where most visitors arrive on mobile. Filtering in JavaScript against data the theme already outputs kept collection pages lean and under the store's control.

The verification step wasn't something a theme app could solve either. It has to connect an order to a WhatsApp conversation and a human decision before fulfilment, which makes it an integration problem (WATI wired into the order flow), not a storefront setting.

Simplified sketch of the filtering approach, not the production code

{%- comment -%} Each product card carries its filterable values {%- endcomment -%}
<li data-product-card
    data-size="{{ product.options_by_name['Size'].values | join: ',' }}"
    data-frame="{{ product.options_by_name['Frame'].values | join: ',' }}">

// Filter in the browser: no app, no page reload
const cards = [...document.querySelectorAll('[data-product-card]')];

function applyFilters(active) {          // e.g. { size: '8x10', frame: 'Gold' }
  cards.forEach(card => {
    card.hidden = !Object.entries(active).every(([key, value]) =>
      !value || card.dataset[key].split(',').includes(value));
  });
}

Results

  • Size, frame and finish chosen on the product page, handled by Liquid logic.
  • No paid filter app. Collections filter with custom JavaScript.
  • Cash-on-delivery orders confirmed on WhatsApp before a personalised portrait goes into production.
